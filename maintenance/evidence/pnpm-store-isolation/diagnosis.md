# Historical pnpm store isolation

Verified official tarball source is preserved with package URL and SRI in source-receipts.json. No repository source, fixtures, recipes, or historical evidence was edited. No user store operation or process termination was performed.

- pnpm 2.17.8 and 2.25.7: `package/lib/node_modules/@pnpm/config/lib/index.js:60` declares `store: path`; lines 114–120 read declared keys via npmConfig.get. `package/lib/createStoreController.js:33` passes `opts.store` to the store-path resolver. `@pnpm/store-path/lib/index.js:23–31` defaults to the home store when no store is supplied, otherwise resolves the supplied absolute path and appends `/2`. `npm_config_store_dir` does not populate `store`. pnpm 3.0.0 retains this historical key.
- pnpm 0.65.0 and 0.67.0: `package/lib/bin/pnpm.js:60` declares `store-path`; line 104 reads it via npm.config.get and camelcases it to storePath. Bundled npm `lib/config/core.js:348–357` strips `npm_config_` and changes underscores to hyphens. Therefore the applicable key is `npm_config_store_path`. `api/extendOptions.js:15` otherwise defaults storePath to `~/.pnpm-store`.
- pnpm 0.60.0: `package/lib/bin/pnpm.js:123` merges getRC('npm') then getRC('pnpm'); line 162 applies camelcaseKeys. Bundled rc `index.js:23` reads appName + '_' environment keys and `lib/utils.js:47–69` strips that prefix without stripping `config_`. Thus `pnpm_store_path` becomes storePath, while npm_config_store_path becomes configStorePath and does not configure the store. `api/extendOptions.js:14` otherwise defaults storePath to `~/.pnpm-store`.

Minimal proposed fix: retain the current npm_config_store_dir and add npm_config_store, npm_config_store_path, pnpm_store_path, all pointing to join(cwd, '.pnpm-store') in execute's child environment. This does not change command evidence or fixture input bytes. No version-boundary assumption is required: each historical implementation reads its recognized key.

Sequential isolated empty-project probes succeeded with the proposed extra environment keys, using the unchanged runner.execute environment override API. pnpm 2.17.8 / Node 11.1.0 created only its requested local .pnpm-store/2; pnpm 0.65.0 and 0.60.0 / Node 10.24.1 created local .pnpm-store/1 and wrote node_modules/.modules.yaml explicitly identifying the isolated path. All three exit codes are 0. Empty projects prove store selection/isolation, not dependency compatibility or lock behavior.
