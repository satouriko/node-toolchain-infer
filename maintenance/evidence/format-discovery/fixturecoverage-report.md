## Historical and transitional results

Yarn 2.4.1, 2.4.3 and 3.0.0 produced metadata 4; 3.1.0 produced 5; 3.2.0, 3.3.0 and 3.8.7 produced 6. The published prerelease 4.0.0-rc.35 produced metadata 7; 4.0.0-rc.53, 4.10.1, 4.12.0 and 4.13.0 produced 8; 4.14.0 produced 9; 4.16.0 and 4.18.0 produced 10. Reusing existing formats avoids redundant recipes.

Legacy pnpm 1.43.1, 2.0.0 and 2.25.7 generated `shrinkwrap.yaml` version 3 and passed frozen installs. The representative 2.25.7 probe was copied unchanged into `pnpm-legacy-shrinkwrap-v3`; its original receipt honestly retains the then-current parser limitation. A follow-up probe read the actual `shrinkwrapVersion` and performed a passing frozen baseline. `legacy-v3-adoption.json` links the exact source and observation.

The released pnpm 2.25.7 artifact exposes `shared-workspace-shrinkwrap` in its bundled config. Enabling its real option and workspace configuration generated version 4 with an `importers` map. The frozen baseline installed the root importer dependency without changing `.npmrc`, `pnpm-workspace.yaml`, `package.json` or `shrinkwrap.yaml`. This is the `pnpm-legacy-shrinkwrap-v4` shared-workspace recipe; it does not claim nested-workspace dependency coverage. `legacy-v4-adoption.json` preserves its source link. Both legacy recipes match the legacy filename explicitly; version 4 additionally requires `sharedWorkspace: true`.

pnpm 3.0.0-alpha.0 generated legacy `shrinkwrap.yaml` version 5 and passed; 3.0.0-beta.0 generated `pnpm-lock.yaml` version 5 and passed. The legacy alpha format remains an investigatory probe rather than an adopted recipe. Wrong-filename probes and initial legacy-parser failures are preserved as incomplete attempts with logs, rather than being reclassified as tool incompatibility. `unsupported-collector-pass` describes the parser status at probe time; it does not negate the recorded frozen-install pass. Core legacy collection support is a separate parent-owned change.

## Reproduction and limits

Run from repository root, for example:

```sh
pnpm exec tsx maintenance/discover-fixtures.ts npm@6.14.18 npm@7.24.2
pnpm exec tsx maintenance/discover-fixtures.ts pnpm@3.0.0 pnpm@3.8.1 pnpm@5.18.11 pnpm@6.0.0
pnpm exec tsx maintenance/discover-fixtures.ts yarn@3.1.0 yarn@4.0.0-rc.35 yarn@4.14.0 yarn@4.18.0
pnpm exec tsx maintenance/discover-fixtures.ts pnpm@2.25.7:shrinkwrap.yaml pnpm@2.25.7:shrinkwrap.yaml:shared
```

The script uses at most two workers and reuses `.cache/maintenance`. Historical Nodes are chosen from the frozen catalog; macOS Node versions before 16 use official x64 artifacts through available Rosetta. Optional dependency bootstrapping uses the existing verified provisioner, and any bootstrap graph/log is copied into durable discovery evidence. Standard formats are adopted only after actual frozen pass; legacy probes are intentionally retained for explicit reviewed adoption.

Coverage remains basic registry dependencies plus the measured root-importer shared-workspace mode. Peer/optional/platform dependencies, nested workspaces, patches, overrides, git/file/tarball sources, alternate linkers/registries and cache-key variants are not established. Further unpublished/unsampled formats are not ruled out. Every published release is being exercised separately by the parent seed runner; this discovery only expands its fixture inputs.
