# node-toolchain-infer

This document supersedes the initial paused design. The approved website is the detailed human/AI rule reference. The package is a standalone Node tool; it is unrelated to litest.

## Scope and interfaces

- Package and CLI name: `node-toolchain-infer`. Host Node >=18. Supported package-manager channels: npm, pnpm, Yarn Classic (<2), Berry (>=2 <6) and native Yarn 6+ (yarnpkg/zpm). Other runtimes and Bun are out of scope.
- `infer({cwd = process.cwd(), node, packageManager, runtime?, catalog?, rules?, signal?} = {})` collects declarations, detects the current runtime, fetches official metadata, and resolves. `node` and `packageManager` are highest-priority direct inputs and accept arbitrary node-semver ranges.
- `collect({cwd, node, packageManager})` returns `{sources, warnings, directories, root}`. It only reads files; it never executes project configuration.
- `resolve({sources, runtime}, catalog, rules = [])` is pure. Result: `{node:{version,reason,bundledNpm}|null, packageManager:{name,version,reason,nodeRange,runtime?}|null, warnings, trace, constraints, dataTimestamp}`.
- `Source`: `{id, kind, target:'node'|'manager'|'lock', value, manager?, format?, features?, depth, rank, path?, conditional?}`. Equal-ranked duplicate sources preserve insertion order. Direct inputs have depth -1.
- `runtime`: `{node,npm,pnpm?,yarn?}`. Node and its bound npm are concrete fallback candidates. Detect bound npm alongside process.execPath; never treat arbitrary PATH npm as its bound npm. Local pnpm/Yarn command versions are optional candidates.

## Collection and precedence

Read the real cwd, its parents, through nearest Git root inclusive; recognize `.git` files as well as directories. If no Git root exists, read only cwd and warn. Outside-root declarations do not participate. Do not scan node_modules.

Sort directory depth first, then this fixed source rank, then insertion order: input.node (1), input.packageManager (2), packageManager (3), pnpm-lock.yaml (4), shrinkwrap.yaml (5), yarn.lock (6), npm-shrinkwrap.json (7), package-lock.json (8), volta.node (9), .node-version (10), .nvmrc (11), .tool-versions nodejs (12), devEngines.runtime node (13), devEngines.packageManager (14), engines.node (15), engines.npm/pnpm/yarn (16, only for the selected type). Precision never changes source priority. Invalid declarations and version conflicts warn; ignore lower-priority conflicts, including their derived conditions. No same-priority errors.

Use semver singleton constraints for exact versions. Preserve PM version ↔ engines.node pairing before merging priorities. Choose retained exact Node, otherwise current Node if valid, otherwise maximum satisfying published Node. Choose retained exact PM, otherwise selected Node's bundled npm or local pnpm/Yarn if valid, otherwise maximum satisfying PM. Default manager identity is npm. Stable runtime candidates remain usable even when absent from registry data; prerelease runtime candidates require a matching retained explicit declaration, whether an exact version or a semver range. Missing engines.node is unknown and does not fabricate a restriction.

## Official metadata contract

`fetchCatalog({fetcher=globalThis.fetch,signal}={})` fetches eight official sources: Node dist/index.json; npm registry npm, pnpm, yarn, @yarnpkg/cli-dist and @yarnpkg/cli; Yarn repo.yarnpkg.com/tags and repo.yarnpkg.com/releases. Native releases use the union of releaseLines.zpm.tags/stable/canary and carry runtime:'native', node:'*'; a stable channel pointing to an RC is still excluded from automatic selection. Explicit native versions and ranges query the same release line and retain only matching prereleases. No executable downloads occur during inference. Duplicate older Yarn declarations prefer cli-dist, then yarn, then cli. Tags absent from registries trigger official tag package-manifest reads through the same request cache. Missing declared Node engines remain null; native executables have known unrestricted host Node requirements. Yarn lock parsing distinguishes native JSON (features.yarnFamily:'zpm') from Classic and Berry YAML; same numeric formats do not share rules. Unknown locks retain manager identity without restricting prereleases admitted by explicit versions or ranges. Maintenance resolves standalone Yarn bundles to immutable Git commits and records their calculated integrity separately from registry provenance. Returns `{schemaVersion:1,generatedAt,sources,nodes:[{version,npm,lts,date}],managers:{npm:[{version,node,sourceUrl?}],pnpm:[],yarn:[]},warnings}`. Normal release lists contain stable versions only. Explicit versions and ranges in API/CLI or project files can admit prereleases using standard semver matching. An exact declaration fetches the requested manifest or release entry; a range fetches matching prereleases from the relevant official lists. Node ranges use the dist, rc, nightly, v8-canary and test indexes. Resolve admits prereleases only while a matching direct declaration is retained. Lockfile inference and local fallback without such a declaration remain stable-only. Node needs its own explicit declaration admitting prereleases even if the selected manager is a prerelease. A caller-provided catalog stays offline. Validate manifest version and engines range; retain node:null for absent engines.

Per-module, in-process, per-URL metadata cache; no default disk cache or shipped release snapshot. Every call conditionally revalidates using ETag/Last-Modified, 304 reuses parsed response; deduplicate in-flight requests. Failed requests can reuse prior successful data with explicit timestamp warning; otherwise throw a structured metadata error. Failed promises must not poison future calls. `infer` can still preserve the known local runtime pair while warning about unavailable metadata, and never claims an unverified global maximum.

`loadCatalog(path)` reads an explicitly supplied maintenance/test snapshot only. `loadRules({compatibilityPath?})` reads the bundled compatibility rules. Rules JSON is `{schemaVersion:1,generatedAt,rules:[{id,manager,match:{format,features?},range,knownBugs?}],observations:[]}`. Do not ship invented mappings or use Renovate.

## Compatibility maintenance

Store real fixtures by manager/file type, format and feature; generate locks with released tools, never edit only lock format numbers. Freeze with npm ci, pnpm --frozen-lockfile, Yarn Classic --frozen-lockfile or Berry/native --immutable. Native Yarn uses the official platform npm artifact with SRI, manifest identity and actual binary version verification; missing host artifacts are incomplete, not incompatible. Verify lock/manifest bytes and actual installed dependencies. Record exact tool, integrity, Node, platform, fixture digest, arguments, output and file hashes. Preserve successful history; only run new combinations. Environment/network failures are inconclusive, not incompatible.

Maintenance-time script generates ranges from confirmed behavior boundaries: unsupported→supported is inclusive lower bound; supported→unsupported is exclusive upper bound; restored support adds an OR interval. Do not truncate at last tested version. Runtime simply matches shipped ranges; unknown format yields `*` with manager identity preserved. Old infer accepts newly published versions admitted by its old table; upgrading infer uses newer measured boundaries. Evidence and inference are distinct. Boundaries must be confirmed, not guessed from sparse samples.

A scheduled/manual GitHub Action runs fixed scripts to discover new stable releases (including old branches), generate existing fixture recipes, test frozen installs, compare with rules, and revisit unresolved maintenance items. New version with same behavior succeeds and records evidence. Unknown formats, parser failures and behavior mismatches are maintenance-required. Network/environment failures are check-incomplete. Save Markdown summary + JSON + reproduction logs before exiting: 0 success, 1 completed with maintenance required, 2 incomplete (also preserve discovered maintenance items). Raw records are appended to a dedicated data branch; main stores fixtures, parsers and generated compatibility table. Pending issues remain red until resolved. Workflow files are delivered locally; no remote creation/push/npm publication is authorized.
